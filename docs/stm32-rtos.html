STM32 RTOS with ZenOS

ZenOS is a compact C++11 real-time operating system for ARM Cortex-M microcontrollers, including STM32-based embedded firmware. This page explains the parts of the kernel that matter when evaluating an RTOS for an STM32 application: scheduling, task resources, timing, inter-task communication, diagnostics and safety configuration.

Why use an RTOS on STM32?

An RTOS can separate firmware into independently scheduled tasks instead of placing every activity in one large main loop. This is useful when an STM32 application has several concurrent responsibilities such as communications, sensor acquisition, control, telemetry, user interfaces or background diagnostics. The RTOS does not remove the need for careful timing analysis; it provides the scheduling and synchronization primitives used to structure that analysis.

ZenOS scheduling on ARM Cortex-M

The current ZenOS scheduler maintains a 32-level ready bitmap and per-priority task queues. The highest eligible priority can therefore be selected without scanning an arbitrary list of all tasks. Periodic tasks also use the kernel's release mechanism. This design is aimed at small microcontrollers where scheduler overhead and predictable behavior matter.

Task resources and memory

ZenOS uses statically allocated task resources rather than a general-purpose heap for task stacks. The application creates the tasks it needs, while available RAM and the target configuration remain the practical resource limits. This makes memory use easier to account for in embedded firmware and avoids requiring a general-purpose dynamic allocator for ordinary task creation.

IPC and synchronization

STM32 firmware commonly has concurrent producers and consumers: an interrupt or DMA path may deliver data while a processing task consumes it, while another task handles communication or telemetry. ZenOS provides events, mutexes, queues and semaphores to coordinate these activities. The appropriate primitive depends on whether the application needs notification, mutual exclusion, buffered data transfer or counting/resource synchronization.

Timing and diagnostics

ZenOS provides kernel timing facilities and runtime diagnostics for embedded development. Monitoring can include CPU usage, stack usage, errors, deadlines, watchdog-related behavior and task integrity depending on the configured features and target. These facilities should be combined with hardware measurements and application-specific timing tests when validating an STM32 product.

Safety configuration

Safety-related mechanisms are configurable rather than a certification claim. Depending on the target and configuration, the project includes mechanisms such as watchdog support, MPU integration where supported, CRC checks, RAM tests and integrity monitoring. Developers remain responsible for system-level hazard analysis, verification, validation and any applicable regulatory or functional-safety requirements.

Getting started with STM32

  1. Review the ZenOS documentation guide and the target configuration.
  2. Integrate the kernel with the STM32 project and its Cortex-M startup/interrupt environment.
  3. Create the application tasks with explicit priorities, stack sizes and timing requirements.
  4. Use the IPC primitives appropriate for the application's communication patterns.
  5. Measure CPU, stack, latency and deadline behavior on the target hardware.

Source and API documentation

The ZenOS GitHub repository contains the kernel implementation and configuration. The complete guide, API tutorial and FAQ provide additional technical context.
