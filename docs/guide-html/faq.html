Frequently Asked Questions

Clear answers about the current ZenOS kernel model.

01

What is ZenOS?

ZenOS is a compact C++11 real-time operating system for ARM Cortex-M embedded firmware, including STM32 projects.

02

How many priorities are available?

The scheduler can be configured with up to 256 priority slots. Priority 0 is reserved for idle, so the maximum application range is 1..255. The default configuration uses 32 slots and therefore priorities 1..31.

03

Does ZenOS allocate a fixed 256-task table?

No. Priority extension storage is derived from the configured number of priority slots. Task resources are statically sized and constrained by available memory and the implementation.

04

What scheduler does ZenOS use?

A ready bitmap identifies active priority levels, each priority has its own ready queue, and the scheduler checks task eligibility before selection.

05

Are periodic tasks real scheduler features?

Yes. A non-zero period_ms is converted to ticks and used with next_run_time as a release gate. Tasks should use os_yield() after their work.

06

What IPC primitives exist?

Events, mutexes, bounded FIFO queues and semaphores are available. ISR-safe variants are provided for operations that can be used from interrupt context.

07

Does ZenOS use a general-purpose heap?

The kernel task model uses static resources rather than a general-purpose heap. Queue capacities and task stacks are explicitly sized.

08

Is ZenOS safety certified?

No. ZenOS provides configurable safety mechanisms and compile-time target-profile checks. Product-level compliance and certification remain the responsibility of the integrator.

09

Where should I start?

Use the complete guide for setup and examples, the architecture page for the kernel model, and the GitHub repository for source code.
