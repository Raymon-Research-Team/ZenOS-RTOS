ZenOS RTOSZenOS RTOS

A compact real-time operating system for ARM Cortex-M with priority-based scheduling, static task resources, bounded IPC, timing, monitoring and configurable safety mechanisms.

یک سیستم‌عامل بلادرنگ سبک برای ARM Cortex-M با زمان‌بندی اولویت‌محور، منابع ایستا، IPC محدود، زمان‌بندی دقیق، پایش و مکانیسم‌های ایمنی قابل پیکربندی.

Quick startشروع سریع

For an STM32CubeMX project, keep SysTick available for ZenOS, move the HAL timebase to a hardware timer such as TIM1, call os_tick() from SysTick_Handler, and compile the ZenOS sources as C++11 with ARM GCC.

در پروژه STM32CubeMX، SysTick را برای ZenOS آزاد نگه دارید، timebase مربوط به HAL را روی تایمر سخت‌افزاری مانند TIM1 قرار دهید، os_tick() را در SysTick_Handler فراخوانی کنید و فایل‌های ZenOS را با C++11 و ARM GCC کامپایل کنید.

#include "ZenOS.hpp"

void task_blink(void) {
    while (1) {
        HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
        os_delay_ms(500);
    }
}

int main(void) {
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    os_init();
    os_task_create(task_blink, 5);
    os_start();
}

Tasks and prioritiesتسک‌ها و اولویت‌ها

Priority `0` is reserved for idle. Application priorities are numeric and higher values mean higher scheduling priority. The configuration supports 2..256 priority slots; at 256 slots the usable application range is 1..255.

اولویت `0` برای idle رزرو است. اولویت‌های کاربردی عددی هستند و عدد بزرگ‌تر یعنی اولویت بالاتر. تعداد اسلات‌ها بین ۲ تا ۲۵۶ قابل تنظیم است و در ۲۵۶ اسلات، محدوده کاربردی 1..255 خواهد بود.

Periodic tasksتسک‌های دوره‌ای

A non-zero period_ms is stored as ticks and enforced through next_run_time. The task should yield after completing its work.

مقدار غیرصفر period_ms به تیک تبدیل و از طریق next_run_time اعمال می‌شود. تسک باید پس از انجام کار CPU را واگذار کند.

void task_sensor(void) {
    while (1) {
        read_sensor();
        os_yield();
    }
}

os_task_create(task_sensor, 10, 100);
Semantics: os_yield() is a scheduling point; os_delay_ms() is a blocking delay; os_delay_us() is a busy-wait.

⚙️ Configurationپیکربندی

#define OS_KERNEL_TICK_PERIOD_US  100UL
#define OS_KERNEL_STACK_SIZE      512
#define OS_KERNEL_MAX_PRIORITIES  32

For the full priority range:

برای استفاده از کل محدوده اولویت:

#define OS_KERNEL_MAX_PRIORITIES 256

This provides application priorities 1..255. The derived extension bitmap and queue storage are calculated automatically.

این تنظیم اولویت‌های کاربردی ۱ تا ۲۵۵ را فراهم می‌کند و حافظه اضافی bitmap و صف‌ها به‌صورت خودکار محاسبه می‌شود.

🧠 Memory modelمدل حافظه

Task stacks and kernel resources are statically sized. The priority extension mechanism adds only the storage needed for configured priority levels above 31. Queue capacities are compile-time values.

پشته تسک‌ها و منابع هسته اندازه‌گذاری ایستا دارند. سازوکار اولویت‌های بالاتر از ۳۱ فقط حافظه لازم برای سطوح تنظیم‌شده را اضافه می‌کند. ظرفیت صف‌ها نیز در زمان کامپایل تعیین می‌شود.

🔧 Troubleshootingعیب‌یابی

SymptomCheck
Tick does not advanceCall os_tick() from SysTick_Handler.
HAL timing conflictsMove HAL timebase to a hardware timer such as TIM1.
Task does not runCheck priority, task state, os_start() order and task yield/block behavior.
Stack faultMeasure peak usage and increase the task stack.
Priority behavior is unexpectedRemember that larger numeric priority means higher priority and priority 0 is reserved.
Priority above 31 rejectedSet OS_KERNEL_MAX_PRIORITIES high enough; 256 enables priorities 1..255.
