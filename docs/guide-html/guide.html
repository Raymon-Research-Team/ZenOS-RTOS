Scheduler and priorities

  • Priority 0 is reserved for the idle task.
  • Application priorities are 1 through 255 when the maximum 256 slots are configured.
  • Higher numeric values represent higher scheduling priority.
  • The scheduler uses a priority bitmap and per-priority ready queues, then scans the configured priority range for an eligible task.
  • Therefore this implementation should not be described as priority-count-independent O(1).
  • The default configuration is 32 priority slots; larger configurations are available when the RAM/flash budget and application design justify them.
Priority 0 compatibility behavior: the current task-creation path maps a requested priority of 0 to application priority 1. Do not use 0 as an application priority.

Timing, delays and periodic tasks

The default kernel tick is 100 µs. The supported configuration range is 100–1000 µs.

os_delay_ms(100);   // blocking delay
os_delay_us(10);    // short busy-wait; does not yield
os_yield();         // request rescheduling
uint32_t t=os_get_ms();
Important: os_delay_ms(0) is not a substitute for a documented blocking delay; use os_yield() when the intent is to give another ready task a scheduling opportunity.

The task control block records period information, but release-period behavior must be described according to the actual scheduler path rather than assuming that the third argument alone guarantees a periodic wake-up.

IPC

Mutex

Mutexes use an IPC priority-ceiling mechanism. This is not priority inheritance.

Queue

Bounded FIFO queues use statically allocated storage and support task/ISR-oriented APIs.

Event

Events provide bounded inter-task signaling and ISR-safe signaling variants.

Semaphore

Counting semaphores provide bounded resource synchronization.

Safety and monitoring

ZenOS contains configurable safety and monitoring mechanisms. Most safety mechanisms are disabled by default; the error log is enabled by default.

MechanismDefaultScope
MPUOffHardware memory protection where supported
RAM integrity testOffBounded SRAM integrity testing; not a claim of a full March C- implementation
CRC checkOffFlash integrity checking
TCB integrity monitorOffTCB integrity diagnostics
Deadline monitorOffDeadline miss detection
Software watchdogOffStuck-task monitoring
Hardware watchdogOffTarget-specific watchdog integration
Error logOnBounded diagnostic ring buffer
Certification boundary: compile-time target profiles and safety mechanisms are engineering controls. They do not by themselves certify ZenOS, a medical device, or an industrial product against IEC 62304 or IEC 61508.

Configuration essentials

#define OS_KERNEL_TICK_PERIOD_US 100UL
#define OS_KERNEL_MAX_PRIORITIES 32
#define OS_KERNEL_STACK_SIZE     512

Priority slots can be configured from 2 to 256. Validate the resulting RAM/flash footprint for the target before selecting a larger configuration.

For the complete configuration reference, see CONFIG_GUIDE.md and Current Implementation.

Minimal application shape

#include "ZenOS.hpp"

void task_main(void) {
    while (1) {
        /* application work */
        os_delay_ms(10);
    }
}

int main(void) {
    os_init();
    os_task_create(task_main, 5);
    os_start();
    while (1) {}
}

Create tasks before os_start(). Use the API reference and current source for exact return values and feature guards.
