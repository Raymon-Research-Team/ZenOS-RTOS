STM32 firmware with ZenOS

Use ZenOS to structure STM32 firmware around explicit tasks, priorities, timing, bounded IPC and measurable runtime behavior.

⚡ Priority scheduling

Up to 256 configured priority slots, with usable application priorities 1..255. The default configuration uses 32 slots.

🧱 Static resources

Task stacks and kernel resources are explicitly sized. The task model does not depend on a general-purpose heap.

🔗 IPC

Events, mutexes, bounded queues and semaphores cover common task coordination patterns.

CubeMX integration

  1. Configure the MCU and peripherals.
  2. Keep SysTick available for ZenOS.
  3. Move the HAL timebase to a hardware timer such as TIM1.
  4. Call os_tick() from SysTick_Handler.
  5. Compile ZenOS sources as C++11 with ARM GCC.

Timing

The default kernel tick is 100 µs. Use os_delay_ms() for blocking delays, os_yield() for a scheduling point, and os_delay_us() only for short busy-waits.

Diagnostics

Use stack and CPU reports during development. Deadline, watchdog, integrity, MPU, RAM and CRC mechanisms are available according to configuration and target hardware.

Recommended path: read the complete guide, configure the STM32 project, create tasks with explicit priorities and stack sizes, choose bounded IPC, then measure timing and memory behavior on the real target.
