3. Your First ZenOS Projectاولین پروژه ZenOS شما

Critical Step 1: Configure LED Pin in CubeMX (Pinout & Configuration → Click on PC13 → Set as GPIO_Output). This is the built-in LED on Blue Pill boards. مرحله حیاتی ۱: پین LED را در CubeMX پیکربندی کنید (Pinout & Configuration → روی PC13 کلیک کنید → GPIO_Output تنظیم شود). این LED داخلی بردهای بلو پیل است.
Critical Step 2: Set HAL Timebase to TIM1 in CubeMX (System Core → SYS → Timebase Source = TIM1). This prevents SysTick conflict with ZenOS. مرحله حیاتی ۲: تایمر HAL را در CubeMX روی TIM1 تنظیم کنید (System Core → SYS → Timebase Source = TIM1). این کار از تداخل SysTick با ZenOS جلوگیری می‌کند.
Critical Step 3: Add os_tick() to SysTick_Handler in Src/stm32fxxx_it.c: مرحله حیاتی ۳: os_tick() را به SysTick_Handler در فایل Src/stm32fxxx_it.c اضافه کنید: 
// In Src/stm32fxxx_it.c
#include "ZenOS.hpp"  // Add at top of file

void SysTick_Handler(void) {
    os_tick();  // ZenOS receives its tick interrupt here
}

3.1 Complete main.cppفایل کامل main.cpp

#include "ZenOS.hpp"

/* ─── Task: Blink LED ─── */
void task_blink(void) {
    while (1) {
        HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);  // Toggle LED
        os_delay_ms(500);                          // Wait 500ms
    }
}

/* ─── Main ─── */
int main(void) {
    HAL_Init();
    SystemClock_Config();  // Generated by CubeMX
    MX_GPIO_Init();        // Generated by CubeMX
    MX_TIM1_Init();        // Generated by CubeMX

    os_init();                          // Initialize ZenOS kernel
    os_task_create(task_blink, 5);      // Create task with priority 5
    os_start();                         // Start scheduler (never returns!)

    while (1) {}  // Never reached
}
That's it! The kernel takes over from os_start() and never returns. Your task runs every 500ms, the LED blinks, and you didn't write a single line of scheduling code. همین! هسته سیستم‌عامل از os_start() کنترل را به دست می‌گیرد و هرگز برنمی‌گردد. تسک شما هر ۵۰۰ میلی‌ثانیه اجرا می‌شود، LED چشمک می‌زند، و شما حتی یک خط کد زمان‌بندی هم ننوشتید.

2. Timing & Delaysزمان‌بندی و تاخیرها

os_delay_ms(100);  // Sleep ~100ms, yield CPU to other tasks
os_delay_ms(0);    // Immediate yield (gives other tasks a chance)

os_delay_us(10);   // Busy-wait ~10µs (blocks CPU — no other task runs!)

uint32_t ms = os_get_ms();    // Milliseconds since boot
uint32_t us = os_get_us();    // Microseconds since boot (DWT counter)
uint32_t tick = os_get_tick(); // Raw tick count
os_delay_us() uses DWT cycle counter for busy-waiting. It does NOT yield the CPU. Use only for very short delays (<1ms).os_delay_us() از شمارنده DWT برای انتظار مشغول استفاده می‌کند و CPU را واگذار نمی‌کند. فقط برای تاخیرهای بسیار کوتاه استفاده کنید.

Elapsed Time Measurementاندازه‌گیری زمان سپری شده

uint32_t t0 = os_get_ms();
// ... do work ...
uint32_t elapsed = os_get_ms() - t0;  // Works even if ms wraps (~49 days)

6. Queues (OS_QUEUE)صفوف (OS_QUEUE)

OS_QUEUE<int, 8> sensor_queue;  // Capacity: 8 items of type int

// Consumer:

    process(value);
}

// ISR-safe:

8. Periodic Tasksتسک‌های دوره‌ای

void task_sensor(void) {
    while (1) {
        uint16_t val = ADC_Read();
        sensor_queue.put(val, 100);
        os_delay_ms(10);  // Yield — next run scheduled at next period
    }
}

os_task_create(task_sensor, 3, 100);  // priority 3, 100ms period
For periodic tasks, use os_delay_ms() at the end of each iteration. The scheduler will automatically wake the task at the next period boundary.برای تسک‌های دوره‌ای، از os_delay_ms() در انتهای هر تکرار استفاده کنید. زمان‌بند به طور خودکار تسک را در مرز دوره بعدی بیدار می‌کند.

    // Hardware watchdog feed (call from dedicated task)
    void task_wdg_feeder(void) {

            os_hw_watchdog_feed();  // Unconditional feed

    }
#endif

    // ROM integrity check
